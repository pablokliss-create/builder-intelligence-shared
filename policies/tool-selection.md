# Tool Selection Policy

No tool is a permanent default.

Choose by current objective and evidence. Evaluate:
- output quality and performance;
- maintainability and ecosystem maturity;
- security and licensing;
- total cost and learning cost;
- portability and lock-in;
- integration with the project's real stack;
- scalability and likely future limits;
- migration/rewrite risk.

Use `approved` to mean vetted for a category, not universally preferred. Use `candidate`/`watch` when evidence is incomplete. Use `deprecated`/`rejected` when continued recommendation is unsafe or no longer justified.
